# KOME Studio

ローカル動画にコメントを重ねて編集・書き出しするブラウザー用ツールです。
**komenagare互換のWeb編集エンジンを取り込み、KOME Studio単独で動作**します。
元の `igarinpiano/komenagare` リポジトリの変更・インストール・起動は不要です。

## はじめに

1. リポジトリ全体をZIPで取得して展開します。
2. `index.html` を Chrome / Edge で開きます。ビルド・サーバーは不要です。
3. 「動画を開く」で各自のローカル動画を選びます。
4. コメントを投稿し、タイムライン・リスト・Vimエディタで編集します。
5. 「保存」でコメントファイルを保存します。
6. 動画に焼き込む場合は「コメ付き書き出し」を使います。

`css/`・`js/`・`lib/` も必要です。HTMLだけを切り離さないでください。
GitHub Pagesでも同じファイル構成で公開できます。
旧来の単体HTML版は **`legacy.html`** にそのまま残しています。
旧版の説明は [docs/LEGACY.md](docs/LEGACY.md) を参照してください。

## 対応内容

| 項目 | 内容 |
|---|---|
| 動画再生 | ローカル動画、再生・シーク・速度・全画面 |
| コメント編集 | 流れる／上下固定、サイズ・色・フォント・表示時間、複数行、プリセット |
| タイムライン | ドラッグ移動、区間調整、ズーム、スナップ、複数選択 |
| テキスト編集 | Vim風エディタ、検索、コメントリスト |
| 変更管理 | 元に戻す・やり直す、変更履歴、マージ時の重複除去 |
| コメント入出力 | komenagare JSON v2、JSONL、CSV、ニコニコXML、旧KOME JSON読み込み／専用ダウンロード |
| 動画出力 | MP4 / MOV / WebM / MKV、高速変換と対応ブラウザーでのリアルタイム録画 |
| 復元 | 単独作業をブラウザーに保存、前回データを明示操作で復元、旧版データの移行 |
| 共同編集クライアント | プロトコル4、衝突解決、送信待ちの保存、参加者表示、追従、プロジェクト切り替え |

コメントは0.01秒単位に正規化します。JSON入力は最大20MB・20,000件・本文とコマンド合計4,000文字／件です。
動画・コメントは通常の単独利用では外部送信されません。動画ファイル自体はブラウザーの作業復元データに保存しません。

## komenagareとファイルを共有する

通常の「保存」はkomenagareのJSON v2を生成します。

```json
{
  "format": "komenagare",
  "version": 2,
  "comments": [
    { "t": 1.25, "cmd": "ue big red", "text": "ここに注目", "id": "01900000-0000-7000-8000-000000000001" }
  ]
}
```

- `t`: 動画開始からの秒数。`id` はUUIDで、読み込み・再保存時に保持します。
- CSVは `time,command,text,id`。改行・カンマ・引用符を含む本文に対応します。
- JSONLは1行1コメントの `{id,t,cmd,text}`。CLIの `comments.jsonl` と同じ項目です。
- XMLは `<packet><chat vpos="125" mail="ue red">本文</chat></packet>`。`vpos` は1/100秒です。
- XML保存では独自の `uuid` 属性を付け、このアプリで再読込するとIDを保持します。他のXML読み込み先でのID保持は保証しません。
- Chrome / Edge のファイルピッカーでは、開いた対応形式へ直接保存できます。保存前の再読み込みに失敗した場合は上書きせず中止します。
- 通常ブラウザーではダウンロード保存です。設定でJSON / CSV / XML / JSONLを選びます。

### 旧KOME Studioからの移行

既存の `[{"time":1.25,"content":"[ue big red]こんにちは"}]` をそのまま開けます。
角括弧コマンドを本文から分離し、`font=gothic` / `font=mincho` を変換します。
`speed=` / `dur=` はkomenagareの `@秒数` に変換します（dur優先）。
先頭の `\[` は文字としての `[` に戻します。未知の角括弧は本文として保持します。

**完全な見た目の互換ではありません。**

- 時刻の数値は保持しますが、流れるコメントはkomenagareの規則で指定時刻の1秒前から現れます。旧版は指定時刻からでした。
- 流れるコメントの `@秒数` は先行1秒を除く長さです。旧 `dur=1` は下限により合計1.1秒になります。
- 等幅フォント、太さ、斜体、コメント個別の不透明度など旧独自装飾は、コマンド文字列に保持し、表示で再現されないことを通知します。
- 描画サイズ・フォント・レーン配置はkomenagare準拠に変わります。旧版と同じ描画が必要なら `legacy.html` を使用してください。
- 旧JSONを開いたファイルハンドルは引き継がず、自動で新形式へ上書きしません。必要なら「名前を付けて保存」で別ファイルを選んでください。
- 旧版へ戻すときは「設定」→「旧KOME形式でダウンロード」。IDやkomenagare独自装飾を完全には持ち戻せないため、通常JSONも残してください。

### 作業復元

単独作業のコメントを `kome-studio-work-v2` に保存します。
同じブラウザー・保存元で旧キー `kome-studio-work-v1` のデータがある場合、復元ボタンを表示します。
復元するまでは保存済みデータを勝手に読み込んだり上書きしたりしません。
旧キーは移行後も削除しません。動画は再選択してください。
ブラウザーの保存領域は消えることがあるため、JSONなどのファイルを正式なバックアップにしてください。
設定・共同編集の送信待ちは `kome-studio` 名前空間に分け、同一オリジンのkomenagareと混ざらないようにしています。

## 共同編集について

**このリポジトリはWebクライアントです。サーバーを起動しません。**
通常の動画編集・ファイル共有・書き出しにはkomenagareを動かす必要はありません。
オンラインで同時編集する場合だけ、すでに用意されたプロトコル4対応ホストが必要です。
ホストなしでは「保存」「マージ」でファイルを受け渡してください。

既存のkomenagare CLIホストを使う管理者は、`--web /path/to/kome-studio` で
このフォルダーを配信元に指定できます。ホストが挿入する `komenagare-host` メタタグで
共同編集が有効になります。サーバーの実装・プロトコルを変更する必要はありません。
参加者はそのホストが配信するKOME Studioを開き、同じ動画を各自選びます。

- 合言葉・OTP認証、衝突解決、送信待ちのIndexedDB保存、変更履歴、プロジェクト切り替えは既存のプロトコル4に従います。
- GitHub Pages / `file://` から別ドメインのホストへ直接接続する機能ではありません。同一オリジン配信を前提とします。
- ホストの標準のWeb自動更新先は変更しません。KOME Studioを配信するには管理者の明示指定が必要です。
- 単独作業の復元データを共同編集プロジェクトへ自動投入しません。
- 実ホストを使った接続・OTP・複数プロジェクト・再接続のE2E検証は今回行っていません。接続機能を本番利用する前に管理者が確認してください。

## 動画書き出しの条件

高速変換はWebCodecsと同梱のMediabunnyを使用します。
対応するコーデックはブラウザー・OS・入力動画によって異なります。
コンテナーを選べることは、すべての環境で任意の動画を書き出せる保証ではありません。
H.264非対応時は別コーデックになることがあります。結果の再生互換性を確認してください。
リアルタイム録画で利用できる形式はMediaRecorder次第です。MOV等は高速変換が必要です。
`file://` はメインスレッド、HTTP(S)配信はWeb Workerで高速変換します。
元の動画と出力ファイルで音声・画質・同期を確認してください。

## 開発・テスト

アプリ自体にNode・npmやビルドは不要です。以下は開発用です。

```sh
npm ci
npm test
npx playwright install chromium
npm run test:browser
```

インストール済みChromiumを使う場合は `CHROMIUM_PATH=/path/to/chromium npm run test:browser`。
ブラウザーテストはローカルのKOME Studioと模擬プロトコル接続先だけを使用し、
元のkomenagareアプリやCLIを起動しません。テスト動画は同梱の人工映像＋440Hz音声です。
検証の詳細は [docs/VALIDATION.md](docs/VALIDATION.md) を参照してください。
